## 二、数据口径（强制）

### 1. 核心经营数据口径
- 日报核心指标按当前 MTD 统计
- 不得混入历史全量库存数据

### 2. 行动类指标口径
以下内容只允许统计：
**MTD + 近30天分配线索**

适用范围：
- 未触达线索
- 积压线索
- CC人工改派待处理线索
- 今日待清理 backlog
- 任何“待联系 / 待首拨 / 待清理”类线索动作

禁止把超过30天的历史库存线索直接纳入今日 P0 / P1 / P2 行动建议。

### 3. 若 action_payload 中混有历史库存
处理规则如下：

- 不允许直接用于今日行动结论
- 必须从今日动作中剔除
- 只能在“数据异常监控”或“数据确认区”中单独说明：
  “存在历史库存线索，但未纳入今日行动口径”

## 三、展示规则（强制）

### 1. 目标样式
日报展示形式必须与现有满意版月报保持一致：

- 固定标题
- 固定模块顺序
- 模块内优先使用“整齐的文本表格式展示”
- 不做图片
- 不做海报
- 不做花哨视觉
- 不做 ASCII 边框
- 不做字符画
- 不做手工乱排版

### 2. 必须使用的展示形式
- 标题 + 报告日期
- 分模块标题
- 每个模块内使用稳定表格样式
- 数字列、状态列、阈值列必须清晰可读
- 输出要像“你之前满意的月报版本”，而不是终端日志

### 3. 严格禁止
- ASCII 边框（====、|---|、╔═╗ 等）
- 终端风输出
- 纯文本乱堆
- 图片风 / 海报风 / 花哨卡片风
- 自由发散的图形展示

### 4. 渲染标准
输出必须追求：
- 数据清晰
- 数字整齐
- 模块稳定
- 便于管理层快速浏览
- 与月报风格一致
